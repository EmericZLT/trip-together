# Umami 产品统计进度

状态：in_progress

## 目标

建立包含历史基线和新增使用趋势的私有 Umami 产品看板。

## 完成条件

采集可信的业务成功事件与页面使用，保留历史总量；建立只供管理员使用的 Umami 看板并核验实际接收。默认不开启本地外发，不改变现有业务权限和数据。

## 核心决策

- 总量直接读取 D1，包括旧用户；Umami 的 visitors 不等于注册用户数。
- 历史创建时间未知，不把历史存量伪装为今日新增。
- Umami 不保证收集接口幂等；网络响应丢失可能导致重发，指标总量以 D1 为准。
- 待提供实例类型、地址、Website ID 和管理凭据；Board 支持需按实例版本核验。

类型检查、生产构建、24 项业务/统计测试、Chromium / WebKit 各 11 项流程测试通过；追加历史基线与 Board 内容保留测试后，4 项独立统计测试通过。代码提交前再次执行源码和计划文档审计。

## 风险与处理

- Umami 实例、版本和令牌尚未提供。已核实官方收集、Board 和 Reports 协议；实际创建和接收必须在用户提供配置后验证。
- 统计为至少一次发送，Umami 不提供幂等保障；总量来自 D1、保留匿名 delivery_id。
- 不转发真实 IP / UA，设备与地域报表没有业务解释意义，已写入看板口径。
